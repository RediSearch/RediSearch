# Migration Stats

Tracks the C to Rust migration by measuring, at a given commit, the production
code size of each language and the number of tests and benchmarks of each.

Files are read from the git object database, so any commit can be measured
without checking it out.

## Usage

```bash
cd src/redisearch_rs
cargo migration-stats measure                 # HEAD
cargo migration-stats measure v8.2.0          # any revision git understands
cargo migration-stats history                 # weekly evolution, see below
cargo migration-stats help <command>          # all the options
```

In a jj checkout, `HEAD` is the parent of the working-copy change; pass
`$(jj log -r @ --no-graph -T commit_id)` to include the working copy.

## What is measured

### Production code

Lines holding code; blank lines, comments, doc comments, `#include`, `use`,
`extern crate` and `mod foo;` declarations are not counted.

- **C / C++**: `.c`, `.cc`, `.cpp` and `.cxx` files under `src/`, except
  `src/redisearch_rs/`. Headers are left out, as are generated files: a `.c`
  next to a Ragel (`.rl`) or Lemon (`.y`) grammar of the same name, or one
  saying it is "generated by" something in its first lines.
- **Rust**: `.rs` files under `src/redisearch_rs/`, split between FFI crates
  (`ffi`, `c_entrypoint/*`, `c_wrappers/*`) and the rest. Left out are:
  - `tests/`, `benches/`, `examples/` directories and `build.rs` scripts;
  - test-only code: items under a `cfg` that cannot hold outside of
    `cfg(test)`, and the files of modules declared that way;
  - `#[test]`, `#[rstest]` and `#[proptest]` functions;
  - crates supporting tests, benchmarks or the build: `tools/*`, `*_bencher`,
    `*_test_utils`, `build_utils`, `redis_mock`, `tracing_assert` and
    `workspace_hack`.

Dependencies vendored in `deps/` are never counted. Code adapted from
third-party sources but maintained in this repository is counted like any
other: for instance `src/util/dict/dict.c`, adapted from Redis, and the Rust
crates forked from third-party ones (`generational_slab`, `thin_vec` and
`utf8parse`).

### Tests

Test definitions, not runs: a parameterized test counts once.

- **C and C++**: Google Test `TEST`, `TEST_F`, `TEST_P`, `TYPED_TEST` and
  `TYPED_TEST_P` in `tests/cpptests/`, plus `TESTFUNC` and minunit
  `MU_RUN_TEST` invocations in `tests/ctests/`.
- **Rust**: unit and integration test functions, i.e. those with a `#[test]`,
  `#[rstest]` or `#[proptest]` attribute (including within `proptest!`), or
  applying an `rstest_reuse` template with `#[apply(...)]`; the `#[template]`
  itself is not a test.

### Benchmarks

- **C++**: Google Benchmark definitions under `tests/`.
- **Rust**: Criterion `bench_function` and `bench_with_input` call sites. A
  call made in a loop or a shared helper counts once.

## History report

`history` measures the first-parent history once per week, from the start of
the port (`--baseline`) to `HEAD` (`--to`), measuring several commits in
parallel. It writes into `--out`, by default `migration-report/` in the cargo
target directory (`bin/redisearch_rs/` at the repository root):

- `report.html`: a standalone page summarizing the evolution, with graphs of
  the code size, the Rust share, the tests and the benchmarks;
- `data.tsv`: one row per sample.

Next to the Rust share of the code, `Rust / (Rust + C and C++)`, it reports that
share with C and C++ frozen at its size at the baseline. New C keeps being written
while porting, so the plain share understates how much has been ported.
